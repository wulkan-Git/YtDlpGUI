# Как опубликовать YtDlpGUI 2.2.0 и сохранить старую версию

## 1. Сначала сохранить старую версию

Если старая версия УЖЕ опубликована как GitHub Release и имеет свой тег, ничего с ней делать не нужно. Не удаляйте старый Release и старый tag — он останется доступным в разделе Releases.

Если старая версия пока находится только в ветке `main` и отдельного Release для неё нет, перед заменой файлов рекомендуется сначала создать для текущего старого состояния отдельный tag/release. Используйте реальный номер старой версии.

Важно: не используйте тег `v2.2.0` для старого состояния.

## 2. Обновить файлы репозитория

В корне репозитория заменить/добавить:

- `README.md` — новый файл из этого пакета;
- `CHANGELOG.md` — новый файл из этого пакета;
- исходники версии 2.2.0.

После этого сделать commit, например:

```text
Release YtDlpGUI 2.2.0
```

## 3. Создать Release 2.2.0

На GitHub:

1. Открыть репозиторий `wulkan-Git/YtDlpGUI`.
2. Справа открыть **Releases**.
3. Нажать **Draft a new release**.
4. В поле **Choose a tag** создать новый тег:

```text
v2.2.0
```

5. Target: ветка/commit с готовым кодом версии 2.2.0.
6. Release title:

```text
YtDlpGUI 2.2.0 — новый интерфейс и выбор точного формата
```

7. В описание Release вставить содержимое файла `RELEASE_2.2.0.md`.
8. Прикрепить готовый файл программы с иконкой.
9. Дополнительно можно прикрепить ZIP с исходниками.
10. Отметить **Set as the latest release**.
11. Не отмечать **Pre-release**, если сборка уже протестирована и готова для всех пользователей.
12. Нажать **Publish release**.

## 4. Рекомендуемые имена файлов релиза

Чтобы всё выглядело аккуратно:

```text
YtDlpGUI-2.2.0.exe
YtDlpGUI-2.2.0-source.zip
```

Если готовая программа поставляется архивом с дополнительными файлами:

```text
YtDlpGUI-2.2.0-win-x64.zip
```


## 6. Проверка после публикации

После создания релиза проверить:

- кнопка `Releases/latest` открывает 2.2.0;
- файл программы скачивается;
- старые Releases по-прежнему отображаются;
- README показывает версию 2.2.0;
- ссылки на `yt-dlp/yt-dlp` работают;
- раздел благодарностей виден;
- ссылка на Star ведёт на ваш репозиторий;
- `CHANGELOG.md` доступен из README.

## Важно про старую версию

Создание нового тега `v2.2.0` и нового Release НЕ удаляет предыдущие теги и Releases. Поэтому старую версию нужно просто оставить на GitHub и не перезаписывать её тег.
